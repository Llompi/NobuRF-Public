Maxwell's equations, solved in a browser tab

NobuRF is a free 3D field solver for antennas and circuit boards. It runs on your GPU through WebGPU, in Chrome or Edge, with nothing to install. On my laptop's GTX 1660 Ti, a 5.8 GHz patch antenna solved in 1.9 s.

How close is it to a reference solver?

I ran the same patch in openEMS, an independent open-source FDTD code, with the same 50 Ω port at the end of the feed line, both on graded meshes with 0.25 mm cells at the copper, and openEMS meshed the way its authors advise for thin copper (grid lines a third of a cell inside each edge). The resonant frequencies agree within 1 %: 5.32 against 5.34 GHz for the edge-fed patch, 5.48 against 5.47 GHz with a 4 mm inset feed. The inset dip reaches −22.1 against −20.4 dB, and the impedance there differs by 2.6 Ω in R and 1.4 Ω in X (44.8 + j5.4 against 42.2 + j4.0 Ω).

On a uniform 0.25 mm grid, which snaps the edges of the inset notch, the inset dip is still too deep (−37 dB). Comparisons with lines on the drawn copper edges read both codes about 1 % low and hide that shared error; the validation report has the full set.

Most of the other checks in the validation report pass. A closed metal cavity resonates within 0.23 % of theory even on a coarse 1 mm grid, a plane wave crosses the grid at the speed it should, and a metal short reflects everything at the right phase. The open boundary reflects −84 dB of a wave hitting it head-on, and doubling the air around the board changes none of the results. What doesn't pass yet: the coarser uniform 0.5 mm grid the live demo uses reads 0.4 to 1.3 % high in frequency against openEMS meshed by its own rule, and 1.7 to 2.4 % against openEMS with lines on the copper edges. Not checked yet: the boundary at oblique angles, and a real board on a VNA.

The validation report has the method, the scripts, every check and its figure. For the openEMS numbers on one page, and how the two tools differ, see NobuRF and openEMS compared.

From one sentence to an antenna

The solver is also a tool for an AI agent. You type one line, such as "a 5.8 GHz patch on a 24 mm FR-4 board". The agent reads it, sets up the design, runs NobuRF solves, changes the geometry between them, and stops when S11 meets the goal it read or when it runs out of solves. You can type a correction while it works, and it reads that with its next solve.

In the recorded run, Kimi K3.1 Pro inside OpenClaw tried 28 designs and settled at 5.83 GHz and −10.6 dB, within 1 % of the target. The run logs have every model request and the final design.

The agent started as my entry for the Kimi K3.1 Pro hackathon on November 21 and 22, 2026. The video shows that run, and the logs compare it with the same model through OpenRouter.

Why I built it

Commercial 3D EM solvers are licensed per seat, at prices set for companies. Students lose access when they graduate, and small hardware teams often tune on the bench instead.

The physics has been public since Maxwell published it in 1865, and the GPU in an ordinary laptop is now fast enough to run it. I wanted to see how much of the expensive part a browser could do, and to have it say plainly where it is wrong.

What's missing

Multi-port S-parameters have one check so far: a two-port low-pass filter from Sheen et al. (1990) rolls off within 1.0 % of the measured curve, while their four-port branch-line coupler doesn't match yet. Conductor loss is checked on a cavity and a microstrip resonator, not yet on a patch. Gerber, DXF and STEP import work but aren't validated yet. Next, in order, each with a validation figure:

  1. Microstrip mode ports.
  2. Thin-wire feeds.
  3. Larger grids through f16 storage and multiple GPUs, for 2.4 GHz boards and arrays.
  4. A fabricated board measured on a VNA.

Run it

The workbench keeps your project on your machine, in this browser's storage. Without WebGPU it solves on the CPU, which is much slower.

To run it from the source instead, with the agent bridge, you need Node.js 20.19 or later, and a browser with WebGPU, such as Chrome or Edge, for GPU solves.

git clone https://github.com/Llompi/NobuRF-Public
cd NobuRF-Public
npm install
npm run dev

Then open http://localhost:5173. On a Windows laptop with two GPUs, start Edge with --force_high_performance_gpu, or Windows hands the work to the integrated one.

Or paste a prompt into your AI agent and let it set NobuRF up for you.

Found a wrong answer? Open an issue with the geometry.
